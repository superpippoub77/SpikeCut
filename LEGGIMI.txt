EDITOR VETTORIALE — LIBRERIA PROGETTI E ACCOUNT UTENTE (API PHP)
=================================================================

COSA CONTIENE QUESTO PACCHETTO
- index.html   → l'editor, apribile in qualunque browser
- api/                     → le pagine PHP che gestiscono account e libreria
- library/                 → cartella dove verranno salvati i progetti
                              (contiene già .htaccess e un indice vuoto)
- users/                    → cartella dove vengono salvati gli account
                              (contiene già .htaccess e un indice vuoto)

COME METTERLO ONLINE (es. hosting Aruba o simile con supporto PHP)
1. Carica TUTTO il contenuto di questo pacchetto (file e cartelle incluse)
   nella stessa cartella sul server, mantenendo questa struttura:

     /qualunque-cartella/
       index.html
       api/
         config.php
         common.php
         register.php
         login.php
         logout.php
         me.php
         forgot_password.php
         reset_password.php
         save.php
         list.php
         load.php
         delete.php
       library/
         .htaccess
         index.json
       users/
         .htaccess
         index.json

2. Verifica che le cartelle "library/" e "users/" siano scrivibili dal
   server web (permessi tipici: 775; su Aruba di norma non serve
   toccare nulla).

3. Apri il sito dal browser passando dall'indirizzo web reale
   (es. https://tuosito.it/projects/spikecut/ — essendo index.html
   si apre automaticamente senza scrivere il nome del file), NON
   aprendo il file in locale con doppio clic: le chiamate all'API PHP
   (e quindi login e libreria) funzionano solo quando la pagina è
   servita da un vero server web.

4. Nella topbar in alto trovi ora il pulsante "👤 Accedi": da lì ci si
   registra, si accede, e si recupera la password. Una volta collegati,
   il menu "File ▾" → "Salva in libreria (server)" chiede anche se
   condividere il progetto con tutti gli utenti oppure tenerlo privato.


ACCOUNT UTENTE E LIBRERIA CONDIVISA
====================================
- Ogni persona che vuole salvare progetti deve creare un proprio
  account (pulsante "👤 Accedi" → "Registrati"): nome utente, email
  e password. Nessun database: gli account sono salvati in un unico
  file in users/index.json, con le password sempre cifrate (mai in
  chiaro).
- Quando si salva un progetto in libreria, si può scegliere se
  tenerlo PRIVATO (visibile solo a chi lo ha creato) oppure
  CONDIVIDERLO nella libreria comune (visibile e apribile da tutti
  gli utenti registrati). Solo il proprietario può modificare o
  eliminare un proprio progetto, anche se condiviso; chi apre un
  progetto condiviso altrui e lo salva ne crea automaticamente una
  copia personale, senza toccare l'originale.
- "Password dimenticata?" nella schermata di accesso invia
  un'email con un link valido un'ora per sceglierne una nuova.
  IMPORTANTE: l'invio usa la funzione mail() di PHP, inclusa in
  quasi tutti gli hosting condivisi (Aruba compreso) ma con
  consegna non garantita al 100% — controlla anche nello spam.
  Se sul tuo hosting mail() non funziona affatto, va configurato un
  vero servizio SMTP lato server (chiedi pure supporto se serve).

PROTEGGERE ULTERIORMENTE L'API CON UNA CHIAVE (opzionale; il login
utente già protegge la libreria, questa è una barriera aggiuntiva
allo stesso livello del server, utile ad es. contro robot automatici)
1. Apri api/config.php e imposta una password a piacere:
     $API_KEY = 'una-password-lunga-e-difficile';
2. Apri index.html con un editor di testo, cerca la riga:
     const API_BASE = 'api/';
   e subito sotto aggiungi:
     const API_KEY = 'una-password-lunga-e-difficile'; // stessa di config.php
   poi cerca la funzione apiFetch e aggiungi l'header, ad esempio:
     opts = opts || {};
     opts.headers = Object.assign({'X-Api-Key': API_KEY}, opts.headers || {});
   (se preferisci, chiedi pure di farlo fare direttamente nell'editor
   la prossima volta che ne parliamo).

NOTE
- Non serve alcun database: ogni progetto è un file .json nella cartella
  "library/", con un piccolo indice (library/index.json) per l'elenco;
  stesso principio per gli account in "users/".
- Le cartelle "library/" e "users/" sono protette da accesso diretto
  via URL (.htaccess con "Require all denied"): si può leggere/scrivere
  solo passando dalle pagine PHP dell'API.
- Se il tuo hosting usa Apache senza mod_authz_core (versioni vecchie),
  l'.htaccess generato include anche la riga "Deny from all" per
  compatibilità con Apache 2.2.
- Se ridistribuisci il progetto via GitHub Actions come da workflow
  incluso, sia "library/**" che "users/**" sono esclusi dal deploy
  automatico: un nuovo push non cancella mai progetti o account già
  presenti sul server.


APRIRE FILE DA GOOGLE DRIVE (opzionale)
========================================
Nel menu "Esporta / Salva" c'è la voce "Apri da Google Drive": apre
il selettore ufficiale di Google, e permette di caricare direttamente
un file .svg o un progetto .json salvato su Drive (sola lettura, non
scrive né modifica nulla su Drive).

Per motivi di sicurezza Google richiede che OGNI sito che usa questa
funzione abbia le proprie credenziali collegate al proprio dominio:
non esiste una chiave "universale" che io possa mettere già pronta
nel file. Vanno create una volta sola, sono gratuite, e servono due
valori da incollare nel file HTML.

1. Vai su https://console.cloud.google.com/ e crea un progetto
   (o usane uno che hai già).

2. Nel menu "API e servizi" → "Libreria", attiva:
   - Google Drive API
   - Google Picker API

3. Vai su "API e servizi" → "Schermata di consenso OAuth":
   - Tipo utente: Esterno (va bene anche se l'app resta "in fase di
     test": basta aggiungere il tuo indirizzo email Google tra gli
     "utenti di test" per poterla usare tu stesso senza revisione
     da parte di Google).

4. Vai su "API e servizi" → "Credenziali" → "Crea credenziali":
   a) "ID client OAuth" → tipo "Applicazione web" → in
      "Origini JavaScript autorizzate" inserisci l'indirizzo esatto
      da cui apri il programma (es. https://tuosito.it, SENZA slash
      finale e senza il nome del file). Copia l'ID client generato
      (una stringa che finisce in ".apps.googleusercontent.com").
   b) "Chiave API" → copiala così com'è (per sicurezza puoi
      restringerla, in "Limitazioni API", alla sola "Google Picker
      API").

5. Apri index.html con un editor di testo, cerca:
     const GOOGLE_CLIENT_ID = '';
     const GOOGLE_API_KEY = '';
   e incolla i due valori ottenuti al punto 4, tra gli apici, es.:
     const GOOGLE_CLIENT_ID = '123456789-abc...apps.googleusercontent.com';
     const GOOGLE_API_KEY = 'AIzaSy...';

6. Salva il file e ricaricalo dal browser (sempre dall'indirizzo del
   sito, non in locale). Alla prima apertura da Drive, Google chiederà
   di autorizzare l'accesso in sola lettura ai tuoi file.

Se lasci i due valori vuoti, la voce di menu resta presente ma avvisa
che l'integrazione non è configurata, senza generare errori altrove.
